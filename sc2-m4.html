Before you begin

Attackers do not need your web page or mobile app to call your API. This module covers the OWASP API Security Top 10, with a focus on the risks that cause the most breaches: object-level and property-level authorisation.

Have crAPI ready, and the mailbox at port 8025.

1

Theory: the OWASP API Security Top 10

The ten API risks, and the practices that prevent them.

APIs are now the main way web and mobile apps exchange data, and attackers call them directly, without any page or app in between. OWASP keeps a separate list for APIs: the OWASP API Security Top 10, last updated in 2023.

IDRiskExampleMain control
API1Broken Object Level AuthorizationChanging an object ID returns someone else's dataCheck ownership of every object on the server
API2Broken AuthenticationWeak tokens, no expiry, no limit on guessingStandard token flows (OAuth 2.0), short expiry, rate limits
API3Broken Object Property Level AuthorizationResponses include hidden fields, or requests can set fields they should notAllow-lists for fields in responses and in requests
API4Unrestricted Resource ConsumptionNo limits on request size, page size or request rateRate limits, maximum page sizes, timeouts, upload limits
API5Broken Function Level AuthorizationA normal user can call an admin endpointRole checks on every endpoint, deny by default
API6Unrestricted Access to Sensitive Business FlowsBots buy all the stock or create thousands of accountsLimits per account and device, bot detection on key flows
API7Server Side Request ForgeryThe API fetches a URL chosen by the callerAllow-list of destinations (Course 1, Module 2)
API8Security MisconfigurationDetailed errors, open CORS, missing TLSHardened settings (Course 1, Module 3)
API9Improper Inventory ManagementOld API versions and test endpoints left runningKeep a list of every API and version; retire old ones
API10Unsafe Consumption of APIsTrusting data from another company's API without checksValidate responses from other APIs like user input

Recommended practices for APIs

  • Authorise every object and every property. For each request, check that the caller may use this object (API1), this function (API5), and each field they read or write (API3).
  • Use separate data types for requests and responses (often called DTOs), listing exactly which fields are allowed. Never send a database record straight back, and never copy a request body straight into one.
  • Limit everything: request rate per user and per source, page sizes, request body size, upload size and processing time.
  • Describe every API in an OpenAPI document, keep an inventory of versions and environments, and turn off what is not used.
  • Treat other APIs as untrusted. Validate their responses, set timeouts, and do not follow their redirects blindly.

Watch out

API3 has two halves. Excessive data exposure: the response includes fields the caller should not see, such as a password hash. Mass assignment: the request can set fields the caller should not change, such as their role. Both are fixed with field allow-lists.

3

Fixes: field allow-lists and limits

A profile API with the weakness and fixed, in each language.

The example is a "my profile" API. With the weakness, the response returns the whole database record (including the password hash and account credit), and the update copies any field from the request (including the role). The fix in every language: an explicit list of fields for the response, an explicit list of editable fields for the update, and a rate limit.

Node.js

Express. The response and the update each use an explicit list of fields.

With the weakness

app.get("/api/users/me", requireLogin, async (req, res) => {
  res.json(await users.findById(req.session.userId));     // every column, including passwordHash
});

app.patch("/api/users/me", requireLogin, async (req, res) => {
  await users.update(req.session.userId, req.body);        // can set role or credit
  res.sendStatus(204);
});

Fixed

const toPublicUser = (u) => ({ id: u.id, name: u.name, email: u.email, phone: u.phone });
const ProfileUpdate = z.object({ name: z.string().max(100), phone: z.string().max(20) }).partial().strict();

app.get("/api/users/me", requireLogin, async (req, res) => {
  res.json(toPublicUser(await users.findById(req.session.userId)));
});

app.patch("/api/users/me", requireLogin, rateLimit({ windowMs: 60_000, limit: 10 }), async (req, res) => {
  const parsed = ProfileUpdate.safeParse(req.body);        // role or credit -> 400
  if (!parsed.success) return res.status(400).json({ error: "Invalid fields" });
  await users.update(req.session.userId, parsed.data);
  res.sendStatus(204);
});
JavaScript (browser)

Fields the page does not show are still in the response for anyone who opens the Network tab.

With the weakness

const me = await (await fetch("/api/users/me")).json();
nameLabel.textContent = me.name;   // passwordHash and credit are in "me" too, just not shown

Fixed

// Ask the server to send only what the page needs (see the Node.js block).
// Hiding fields in the page is not protection.
const me = await (await fetch("/api/users/me")).json();   // { id, name, email, phone }
nameLabel.textContent = me.name;
TypeScript

Separate types for the database record and the API response make leaks visible in review.

With the weakness

interface UserRecord { id: number; name: string; email: string; phone: string;
                       role: string; passwordHash: string; credit: number; }

app.get("/api/users/:id", async (req, res) => {
  const u: UserRecord = await users.findById(req.params.id);   // no ownership check
  res.json(u);
});

Fixed

interface PublicUser { id: number; name: string; email: string; phone: string; }

function toPublicUser(u: UserRecord): PublicUser {
  return { id: u.id, name: u.name, email: u.email, phone: u.phone };
}

app.get("/api/users/:id", requireLogin, async (req, res) => {
  if (req.params.id !== String(req.session.userId)) return res.sendStatus(404);   // API1
  res.json(toPublicUser(await users.findById(req.params.id)));                      // API3
});
Python

FastAPI and pydantic: one model for the response and one for the update.

With the weakness

@app.get("/api/users/me")
def me(user: User = Depends(current_user)):
    return user.__dict__                       # every field

@app.patch("/api/users/me")
def update(body: dict, user: User = Depends(current_user)):
    for k, v in body.items():
        setattr(user, k, v)                    # mass assignment

Fixed

class PublicUser(BaseModel):
    id: int
    name: str
    email: str
    phone: str

class ProfileUpdate(BaseModel):
    model_config = ConfigDict(extra="forbid")  # role or credit -> 422
    name: str | None = Field(default=None, max_length=100)
    phone: str | None = Field(default=None, max_length=20)

@app.get("/api/users/me", response_model=PublicUser)
def me(user: User = Depends(current_user)):
    return user

@app.patch("/api/users/me", response_model=PublicUser)
def update(body: ProfileUpdate, user: User = Depends(current_user)):
    for k, v in body.model_dump(exclude_unset=True).items():
        setattr(user, k, v)
    return user
Java

Spring Boot with request and response records.

With the weakness

@GetMapping("/api/users/me")
public User me(Principal p) { return users.findByEmail(p.getName()); }   // the entity, all fields

@PatchMapping("/api/users/me")
public void update(@RequestBody User changes, Principal p) {
    users.save(merge(users.findByEmail(p.getName()), changes));       // any field
}

Fixed

public record PublicUser(long id, String name, String email, String phone) {}
public record ProfileUpdate(@Size(max = 100) String name, @Size(max = 20) String phone) {}
// spring.jackson.deserialization.fail-on-unknown-properties=true

@GetMapping("/api/users/me")
public PublicUser me(Principal p) {
    User u = users.findByEmail(p.getName());
    return new PublicUser(u.getId(), u.getName(), u.getEmail(), u.getPhone());
}

@PatchMapping("/api/users/me")
public void update(@Valid @RequestBody ProfileUpdate body, Principal p) {
    User u = users.findByEmail(p.getName());
    if (body.name() != null) u.setName(body.name());
    if (body.phone() != null) u.setPhone(body.phone());
    users.save(u);
}
C#

ASP.NET Core with request and response records, and the built-in rate limiter.

With the weakness

[HttpGet("api/users/me")]
public async Task<User> Me() => await _db.Users.FindAsync(CurrentUserId());   // the entity

[HttpPatch("api/users/me")]
public async Task Update(User changes)
{
    _db.Users.Update(changes);                                               // any field
    await _db.SaveChangesAsync();
}

Fixed

public record PublicUser(int Id, string Name, string Email, string Phone);
public record ProfileUpdate([MaxLength(100)] string? Name, [MaxLength(20)] string? Phone);

[HttpGet("api/users/me")]
public async Task<PublicUser> Me()
{
    var u = await _db.Users.FindAsync(CurrentUserId());
    return new PublicUser(u!.Id, u.Name, u.Email, u.Phone);
}

[EnableRateLimiting("profile")]
[HttpPatch("api/users/me")]
public async Task Update(ProfileUpdate body)
{
    var u = await _db.Users.FindAsync(CurrentUserId());
    if (body.Name is not null) u!.Name = body.Name;
    if (body.Phone is not null) u!.Phone = body.Phone;
    await _db.SaveChangesAsync();
}
Recommended practice
  • Generate or check your OpenAPI document against the code, so undocumented endpoints and fields stand out.
  • Write tests that send extra fields (such as role) and check they are refused.
  • Apply different rate limits to cheap and expensive endpoints, and to signed-in and anonymous callers.

Lab: read another user's data, then control the fields

Part A: Broken Object Level Authorization in crAPI. Part B: field allow-lists in your language.

Part A: read another user's vehicle location in crAPI

Start crAPI as in Module 0, and open http://localhost:8888.

  1. Sign up with a made-up email address, and sign in.
  2. Open the test mailbox at http://localhost:8025. crAPI has sent your vehicle's VIN and PIN code. Back in crAPI, select Add a Vehicle and enter them.
  3. Open the developer tools and the Network tab. On the dashboard, select Refresh Location for your vehicle. Find the request to /identity/api/v2/vehicle/<your vehicle ID>/location.
  4. Open the Community page. In the Network tab, open the response for /community/api/v2/community/posts/recent. Each post's author has a vehicleid. Copy one that is not yours.
  5. Right-click the location request from step 3 and choose Copy as fetch. Paste it into the Console, replace your vehicle ID in the address with the one you copied, and run it. Add .then(r => r.json()).then(console.log) at the end to see the result.

The response shows another user's vehicle location. The API checked that you were signed in, but not that the vehicle was yours. This is API1, Broken Object Level Authorization.

Think about it

Two problems combined here: the community API exposed vehicle IDs that it did not need to share (API3), and the location API did not check ownership (API1).

Part B: control which fields go in and out

Each starter has a user record with fields the API must never return (role, passwordHash, credit), and four profile updates. Complete the two functions:

  1. toPublicUser returns only id, name, email and phone.
  2. applyProfileUpdate returns nothing (null or None) if the update contains any field other than name and phone, so the caller prints rejected.

The expected Node.js output is below. Other languages may add spaces in the JSON, which is fine.

1 {"id":7,"name":"Asha","email":"asha@example.com","phone":"0000"}
2 {"id":7,"name":"Asha R","email":"asha@example.com","phone":"0000"}
3 rejected
4 rejected
5 {"id":7,"name":"Asha R","email":"asha@example.com","phone":"0123456789"}

profile.mjs

// TODO: return only id, name, email and phone
function toPublicUser(user) {
  return user;
}
// TODO: return null if body has any field other than name or phone
function applyProfileUpdate(user, body) {
  return { ...user, ...body };
}

let user = { id: 7, name: "Asha", email: "asha@example.com", phone: "0000",
             role: "customer", passwordHash: "$argon2id$v=19$m=65536...", credit: 0 };
const updates = [{ name: "Asha R" }, { role: "admin" }, { name: "X", credit: 1000 }, { phone: "0123456789" }];

console.log("1", JSON.stringify(toPublicUser(user)));

  const next = applyProfileUpdate(user, body);

type User = { id: number; name: string; email: string; phone: string;
              role: string; passwordHash: string; credit: number };
type PublicUser = Pick<User, "id" | "name" | "email" | "phone">;

// TODO: return only id, name, email and phone
function toPublicUser(user: User): PublicUser {
  return user;
}
// TODO: return null if body has any field other than name or phone
function applyProfileUpdate(user: User, body: Record<string, unknown>): User | null {

Java

Profile.java

import java.util.*;

public class Profile {
    // TODO: return only id, name, email and phone
    static Map<String, Object> toPublicUser(Map<String, Object> user) {
        return user;
    }
    // TODO: return null if body has any field other than name or phone
    static Map<String, Object> applyProfileUpdate(Map<String, Object> user, Map<String, Object> body) {
        Map<String, Object> next = new LinkedHashMap<>(user);
        next.putAll(body);
        return next;
    }

    // Writes a flat map of strings and numbers as JSON.
    static String toJson(Map<String, Object> m) {
        StringJoiner j = new StringJoiner(",", "{", "}");
        m.forEach((k, v) -> j.add("\"" + k + "\":" + (v instanceof Number ? v : "\"" + v + "\"")));
        return j.toString();
    }

    public static void main(String[] args) {
        Map<String, Object> user = new LinkedHashMap<>();
        user.put("id", 7); user.put("name", "Asha"); user.put("email", "asha@example.com");
        user.put("phone", "0000"); user.put("role", "customer");
        user.put("passwordHash", "$argon2id$v=19$m=65536..."); user.put("credit", 0);
        List<Map<String, Object>> updates = List.of(
            Map.of("name", "Asha R"), Map.of("role", "admin"),
            Map.of("name", "X", "credit", 1000), Map.of("phone", "0123456789"));

        System.out.println("1 " + toJson(toPublicUser(user)));
        for (int i = 0; i < updates.size(); i++) {
            Map<String, Object> next = applyProfileUpdate(user, updates.get(i));
            if (next == null) System.out.println((i + 2) + " rejected");
            else { user = next; System.out.println((i + 2) + " " + toJson(toPublicUser(user))); }
        }
    }
}

static Dictionary<string, object>? ApplyProfileUpdate(Dictionary<string, object> u, Dictionary<string, object> body)
